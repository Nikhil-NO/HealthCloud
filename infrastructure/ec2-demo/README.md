# Always-on demo (EC2) — `infrastructure/ec2-demo/`

A **permanent, always-up** deployment of HealthCloud on **one cheap EC2 box**, so the resume /
LinkedIn / portfolio link is clickable 24/7 (recruiters visit at unpredictable times). It is a
**separate, self-contained Terraform config** from [`../terraform/`](../terraform/) — the on-demand
ECS/Fargate/RDS/CloudFront showcase — and shares nothing with it (its own state key, its own Cognito
pool), so a `terraform destroy` of the ECS stack never affects this demo.

> **Same app, cheaper hosting.** The full production-shape AWS architecture (ECS Fargate, RDS,
> CloudFront, MSK-less event-driven design, Terraform, evidence pack) still lives in the repo as the
> engineering showcase. This box just gives the *live link* an affordable always-on home. AWS
> credibility comes from the built code + IaC + evidence, not from where the live link points.

## Architecture

```
internet ──▶ Caddy (:443, auto Let's Encrypt TLS)
                 └─▶ frontend nginx (:8080, serves the SPA + reverse-proxies /api,/actuator,/oauth2)
                        └─▶ backend (Spring Boot BFF, :8080)
                               └─▶ postgres (:5432, Docker volume)
```

- **One `t4g.micro`** (ARM64/Graviton — the app images are `linux/arm64`) running Amazon Linux 2023.
- The whole app runs as **Docker Compose** on the box (`docker-compose.yml` + `Caddyfile` here are the
  exact files copied to it). Images are pulled from **GHCR** (published by CI).
- **Caddy** obtains + renews a free **Let's Encrypt** cert automatically once DNS points at the box.
- **Its own Cognito pool** (`demo,cognito` profile) — real OIDC login, the branded hosted UI, 14
  synthetic users (both orgs × 7 roles). No `local` profile → the dev-login bypass is absent, exactly
  like the ECS deploy.
- **Secrets** (DB password, audit HMAC, Cognito client secret) are generated by Terraform and
  delivered via **SSM Parameter Store (SecureString)** — never baked into user-data. The box reads
  them once at boot with its instance role.
- **No SSH** — shell access is via **SSM Session Manager** (`aws ssm start-session --target <id>`).

## Prerequisites (one-time)

1. **GHCR images are public.** In the GitHub repo → Packages, make `healthcloud-backend` and
   `healthcloud-frontend` public (else the box can't pull them). CI already builds/pushes them on
   `main`.
2. **Domain owned:** `healthcloud-demo.com` (Namecheap). DNS is pointed at the box *after* apply.
3. AWS creds for the account, Terraform ≥ 1.9, the state bucket (already created by
   `../terraform/bootstrap`).

## Cost

- `t4g.micro` + a 20 GB gp3 volume + one **attached** Elastic IP: free-tier eligible; after any free
  window ≈ **$6–10/mo**, covered by AWS credits. Cognito, SSM Parameter Store (standard), and the
  Let's Encrypt cert are **$0**.
- Everything is on ONE box (no ALB, no RDS, no CloudFront, no NAT) — that's the whole point vs the
  ~$70/mo ECS stack.
- ⚠️ An Elastic IP is only free **while attached to a running instance**; a `destroy` releases it.

## Deploy (all AWS steps are approval-gated per the project's AWS boundary rule)

```bash
cd infrastructure/ec2-demo
terraform init                 # reads/writes remote state (needs AWS creds)
terraform plan                 # review — creates ~14 Cognito users + 1 box + IP + SSM param + IAM
terraform apply                # FIRST cost step — announce + get go-ahead first

# then follow the printed `next_steps`:
#   1. DNS at Namecheap:  A  @ -> <elastic_ip> ,  A  www -> <elastic_ip>
#   2. wait for DNS; Caddy issues HTTPS automatically
#   3. ./set-demo-passwords.sh "$(terraform output -raw cognito_user_pool_id)"
#   4. open https://healthcloud-demo.com and sign in as any role
```

Offline check only (no AWS calls): `terraform init -backend=false && terraform validate`.

## Updating the running app

CI publishes new images to GHCR on every `main` push. To roll the box forward:

```bash
aws ssm start-session --target "$(terraform output -raw instance_id)"
cd /opt/healthcloud && docker compose pull && docker compose up -d
```

(Or bump `image_tag` / edit user-data and `terraform apply` — `user_data_replace_on_change` recreates
the box, which re-seeds the DB.)

## Teardown

```bash
terraform destroy    # removes the box, IP, Cognito pool, SSM param, IAM — back to ~$0
```

## Notes / honest limitations

- **Single box, single AZ, no backups** — appropriate for a synthetic-data portfolio demo, not a
  production posture (the ECS stack + evidence pack document the production-shape design).
- Postgres data lives in a Docker volume on the instance's EBS; recreating the instance re-seeds it.
- Caddy→nginx→backend is an internal HTTP hop, so the OIDC `redirect_uri` is **pinned** to the HTTPS
  domain via env (same lesson as CloudFront→ALB); the `SESSION` cookie isn't force-`Secure` because
  the viewer hop is always HTTPS via Caddy.
- **Synthetic data only.** The published demo passwords are intentional (throwaway Cognito accounts
  reaching no real data).
